Model boundaries, source evidence, and how to read the simulation
  • This is an educational discrete-time model of branch 967697c335282878d11fccc8fddbe1f1bba1cbf5. It makes no network calls to Kafka, a catalog, or S3. Example Parquet/Avro/JSON contents are logical representations, not binary files or complete REST payloads.
  • One unpartitioned format-v2 append table, one control partition, and one elected coordinator are modeled. Five Kafka partitions do not imply five Iceberg partitions or files. The owner of orders-0 hosts the coordinator.
  • Current branch behavior: physical replay suppression in Channel.consumeAvailable(), monotonic offset maps, and count-based readiness. PR #17925's expected-set readiness is not in this branch and is not silently applied here.
  • Virtual ticks expose operations that run concurrently in production. Worker subscription delivery, file uploads and REST commits have fixed demonstration latency. Byte encoding, producer fencing, real assignor/generation transitions, request retries, multi-table commits and distributed scheduling are not emulated. Failing only the coordinator is a controlled fault injection: production also propagates its termination to the hosting task. Use Restart connector to model replacement of all task-local state.
  • Control-event offsets include one illustrative transaction-marker gap per transaction. Source offsets in this demo are consecutive. Every worker handoff atomically publishes its file events and source offsets; the table commit and coordinator checkpoint are separate steps.
  • Completed files are put into the simulated S3 store only when their upload finishes. Local staging is shown separately. File rolling uses a row threshold for visibility; real writers use size targets and encoding-specific buffering. Open staging abandoned on restart is not shown as an S3 object. Connect's flush() callback does not force an Iceberg commit: it calls committer.save(null) to service worker control events. StartCommit invokes completeWrite(), which finishes the open files. The simulator's ticks model this servicing; Advance to commit moves virtual time to the coordinator interval.
  • Manifests use a simple pedagogical layout with reuse of earlier manifests for append-only snapshots. Actual Iceberg merging, filenames, location providers and manifest contents can differ. Catalog publication points at new table metadata; snapshots do not copy all rows.
  • valid-through-ts is the minimum of reported last-record timestamps when all are non-null and the commit is full. It is not a guarantee about late/out-of-order business events. Example timestamps increase with virtual time; real Kafka timestamps need not.
  • Coordinator replacement resumes its Kafka checkpoint; with no checkpoint it defaults to latest. Snapshot ancestry provides the table replay filter. Retention/expiration are not simulated. S3 objects and catalog state are assumed to survive a connector restart.
  • The demo caps produced records at 300 to keep the log inspectable. Keyboard controls and reduced-motion preferences are supported. Changing the display speed affects wall-clock playback only.
